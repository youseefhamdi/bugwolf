# Mandatory Deep-Research Loop

> **Rule:** research is not a one-time Turn-0 step. Techniques, CVEs, and bypasses age in weeks. A stale skill finds fewer bugs. **Every real hunt/recon/novelty run executes the checkpoint sequence strictly in order and refreshes the current surface, maps, payloads, and knowledge base before continuing.** Full accurate picture > fast-but-stale hunt.

The enforced sequence is `pre-hunt → post-recon → post-maps → bypass → post-findings → escalation → pre-report`. `hunt.py` runs the first four before target requests and the final three after observations; `recon_engine.sh` runs the pre-hunt checkpoint before recon and the post-recon/post-maps sequence afterward; `zero_day.py` runs the same before and after local candidate analysis. Each sequence writes `research/<target>/sequence.json` with order, pending searches, and `latest_ready` status.

Use `tools/research_loop.py --checkpoint <ckpt> --mode <modes> --execute --target T` to execute one checkpoint. For a mandatory ordered run use `--sequential --phase full` (or `before_hunt`, `recon`, `after_findings`): it fetches every canonical source via `urllib`, runs the configured live search provider, and persists each checkpoint plus `sequence.json`. `SERPER_API_KEY` / `RESEARCH_SEARCH_API_KEY` and an HTTPS `RESEARCH_SEARCH_API_URL` enable current web search. With `--require-latest`, bundled references are not substituted for live results; unavailable searches are recorded as pending and `latest_ready` is false. Then **write what changed back into the hunt state** (the maps / confidence / payloads).

## The 5 Checkpoints

| # | Checkpoint | When it fires | What to research | What it must update |
|---|---|---|---|---|
| R1 | **Pre-hunt baseline** | Before Turn 1, once per session | Latest Top-10 lists (web/API/LLM/agentic/mobile/cloud/CI-CD), CWE Top 25, CISA KEV | `research/{target}/baseline.md` — the reference frame the whole hunt scores against |
| R2 | **Post-recon** | After Turn 1 (asset/stack discovery) | Latest CVEs + vendor advisories for the **exact** detected framework/library versions | `maps/asset.md` tech+version rows; a `research/{target}/cves.md` table (version → CVE → KEV?) |
| R3 | **Post-maps** | After Turn 1.75 (maps built) | Fresh technique payloads for the mapped attack-surface classes (RAG/embedding, K8s escape, intent redirection, etc.) **+ target-specific wordlists (vhosts/params/dirs/payloads) generated by `wordlist_gen.py`** — the `payloads` list feeds the generator's mined tokens back in: redirect/destination params become open-redirect/SSRF sinks, mined param names become reflection/injection markers, and mined path segments prefix traversal probes | `maps/*.md` gap signals; the attack-vector payloads the agents will fire; `research/{target}/post-maps/wordlists/*.txt` |
| R4 | **Post-findings** | Turn 4, before triage/gates | Latest bypasses + comparable disclosed reports + acceptance rates for the **specific bug classes found** | each finding's confidence + CWE + dedup check; `research/{target}/findings-research.md` |
| R5 | **Pre-report** | After gates, before writing the report | Current program scope/rules, severity table, recent similar disclosures | report platform-fit + severity calibration + duplication |

**Ordering matters:** R2 research into exact versions beats generic R1 research; R4 research into the exact bug class found beats generic R3 research. The mandatory coordinator never launches checkpoint workers in parallel. Each checkpoint narrows the research to what the hunt has *actually* uncovered, which is how a stale generalist becomes a current specialist.

## The 2 Event-Driven Checkpoints (fire mid-hunt, not in sequence)

R1–R5 fire on a schedule. Two more fire **on a trigger**, the instant the hunt needs them:

| # | Checkpoint | Fires | What to research | What it must update |
|---|---|---|---|---|
| R6 | **Bypass** | Immediately when a probe is blocked (403 / WAF / rate-limit / sanitization / filter / honeypot) | The latest bypasses for that **exact** defense + bug class (`{defense} {bug_class} bypass`, filter-evasion payloads, WAF-specific techniques) | The payloads that get re-fired against the blocker; `waf-bypass-agent`'s technique list |
| R7 | **Escalation** | Immediately on every Medium/Low finding, before it is written off or downgraded | Comparable High/Critical disclosures, bounties, and chain partners (`{bug_class} high critical disclosed report`, `{bug_class} chained ATO/RCE`) + sibling-surface recon | The finding's severity + confidence + chain partners; whether it rises to High/Critical |

**Why they exist:** a blocked probe and a sub-critical finding are the two moments a hunt silently loses a High/Critical. R6 stops the agent from abandoning a surface just because the first payload was filtered; R7 stops it from downgrading a Medium that had an undiscovered chain partner. Both are mandatory — a blocker with no bypass research, or a Medium with no escalation search, is the same failure as skipping R4/R5.

## Authoritative Sources (fetch these, don't rely on memory)

| Surface | Canonical source |
|---|---|
| Web/API | OWASP Top 10 2025 · CWE Top 25 (cwe.mitre.org) |
| LLM / agentic / MCP | OWASP GenAI LLM Top 10 2026 (github.com/GenAI-Security-Project/GenAI-LLM-Top10) · OWASP Agentic Top 10 2026 (ASI01–ASI10) |
| Mobile | OWASP MASVS / MASWE / MASTG (mas.owasp.org) |
| Cloud / infra | OWASP Cloud-Native Top 10 · CSA Top Threats |
| CI/CD | OWASP Top 10 CI/CD Security Risks (CICD-SEC-1..10) |
| Smart contracts / DeFi | Rekt.news leaderboard · Immunefi / Sherlock / Code4rena findings |
| Exploited-in-the-wild | CISA KEV catalog · GitHub Security Advisories (GHSA) · NVD |
| Bypasses / chaining | OWASP GenAI Exploit Round-up · vendor advisories |

**Local data accelerators:** clone `rix4uni/cvemapping` once — it maps CVE IDs to affected products/versions, so R2 exact-version lookups hit a local file instead of re-searching NVD per version. `resolvers.txt` + `SecLists` (see `references/recon-tooling.md` §17) seed the recon brute/resolve phases.

**Synthesis rule (every checkpoint):** research is only done when its output lands in the hunt. A CVE researched but not written to `maps/asset.md` or a payload researched but not fired is wasted time. The persisted research directory (`research/{target}/{checkpoint}/SUMMARY.md` + `results.json` + `sources/*.md`) is the tamper-evident record of *what was refreshed and when* — the same discipline as the ledger.

| `--web` | WAF bypass (15 techniques), HTTP smuggling/cache, auth/IDOR chaining |

## Anti-Patterns

- **Do not** do one big research dump at Turn 0 and never again — that is the failure mode this loop exists to prevent.
- **Do not** research generically what the hunt has already made specific — always re-query with the concrete versions/classes discovered.
- **Do not** skip R4/R5 because "we already know this bug class" — bypasses and program rules change; check both before reporting.
- **Do not** trust a source that is a blog post over a canonical source — prefer OWASP/MITRE/CISA/vendor/advisory first, blogs only to fill gaps.
- **Do not** fire a static wordlist or payload — generate a target-specific one first via `tools/wordlist_gen.py --target T --mode <vhosts|params|dirs|payloads> --research` (mines the target surface, derives wordforms, applies the tech stack, and researches the internet).
